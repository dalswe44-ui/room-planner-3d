# T-004 작업 보고 (furniture-placement)

에이전트가 최종 응답으로 돌려준 보고서를 헤드가 저장했다. App.tsx는 에이전트가 확인할 때만 임시로 고쳤고 원래 파일로 되돌렸다(md5 수정 전과 같음). 조립은 헤드가 했다.

## 1. 변경 파일

모두 `src/furniture/` 아래의 새 파일.

| 파일 | 내용 |
|---|---|
| `placement.ts` | 순수 계산. 상수(`GRID_MM=10`, 치수 10 ~ 10000, `WARN_MIN_MM=1`, 기본 이름 "가구"), `footprintSize`·`footprint`(회전 후 발자국), `footprintsOverlap`, `isOutsideRoom`, `computeItemStatuses`, `snapCenter`, `grabOffset`·`dragCenter`, `nextRotation`, `wallDistances` |
| `usePlacement.ts` | `createPlacementHandlers(getState)`(React 없이 테스트)와 `usePlacement()` |
| `useItemStatuses.ts` | 가구, 방 꼭짓점, `dragPreview`를 구독해 상태 계산 |
| `FurniturePanel.tsx` | 추가 폼, 목록, 선택한 가구의 편집·회전·삭제, 경고 문구, 벽까지 거리 |
| `furniture.css` | 패널 스타일(app.css 변수만 사용) |
| `placement.test.ts`, `usePlacement.test.ts`, `FurniturePanel.test.tsx` | 단위·컴포넌트 테스트 60개 |

## 2. 구현한 계약과 SPEC 항목

계약: CONTRACT 5절 `FurniturePanel()`, `usePlacement()`, `useItemStatuses()`. 6절 핸들러 4개. 8절 식별자 전부(추가 폼 `furniture-name/w/d/h/add`, 목록 `item-row`(`data-item-id`, 선택 시 `aria-pressed="true"`), 선택한 가구 `item-name/w/d/h/color`, `item-dist-0..3`(숫자만), `item-rotate`, `item-delete`, `item-status`). 선택이 없으면 선택한 가구 요소는 없고, 경고가 없으면 `item-status`도 없다.

끌기: 누르면 선택하고 grab offset(중심 − 누른 지점)을 저장. 끄는 동안 `setDragPreview`만, 떼면 `snapCenter` 위치를 `updateItem`으로 한 번 확정하고 `dragPreview`를 지움. 움직이지 않고 떼면 확정하지 않음(P-4). `viewMode !== '2d'`이면 선택만. `onBackgroundTap`은 선택 해제. 끄는 중 삭제되면 확정하지 않음.

스냅: 회전을 반영한 발자국의 왼쪽·위쪽 변을 10의 배수로 반올림한 뒤 중심을 정수 mm로. 홀수 치수의 0.5 mm 어긋남은 알려진 한계. -0은 0으로.

경고: 겹침 = x, z 모두 1 mm 이상 겹침(맞닿음·0.5 mm는 아님). 이탈 = 경계 밖 1 mm 이상. 90·270도에서 폭·깊이 교환, 끄는 중에는 `dragPreview` 위치로 판정. 막지 않음. 문구 "겹침: …", "방 밖: …"(동시에 나올 수 있음).

벽까지 거리: [minZ, width − maxX, depth − maxZ, minX], 밖으로 나간 쪽은 음수. `formatLength`로 현재 단위. 이름표 "위쪽 벽 (벽 0)", "오른쪽 벽 (벽 1)", "아래쪽 벽 (벽 2)", "왼쪽 벽 (벽 3)".

추가 폼: 거부 상태인 칸이 있으면 버튼 `disabled`, 제출 핸들러도 다시 확인. 제출 시 먼저 `document.activeElement.blur()`(iOS), 그다음 ref에서 값을 읽음. 이름이 비면 "가구".

선택한 가구의 편집 칸: `onValidityChange`를 넘기지 않음(T-002b 미해결 2번). 이름은 Enter나 포커스 이탈 때 확정.

Enter 제출을 form submit으로 한 근거: `LengthInput`은 keydown 안에서 `onCommit`·`onValidityChange`를 부르므로 뒤따르는 암묵적 제출 때 값이 이미 반영됨. 제출 핸들러는 ref를 읽음. Chrome 확인: 올바른 값에서 Enter → 추가·포커스 BODY, `abc` 후 Enter → 추가 안 됨, `1700`으로 고치고 Enter → 추가됨.

## 4. 남은 문제

1. e2e 주의(qa-verifier): 오류 칸을 고친 직후 확정 전에는 `furniture-add`가 `disabled`라 Playwright `locator.click()`이 기다리다 시간 초과. Tab으로 확정 후 누르거나 `page.mouse.click`으로 좌표를 누를 것. 실제 사용자는 한 번에 추가됨.
2. 추가 폼의 Enter는 제출이다. e2e에서 `furniture-*` 칸에 "값 + Enter"를 쓰면 추가된다.
3. 추가 폼 처음 치수 600·600·600 mm는 SPEC에 없는 값.
4. 회전은 중심 기준. 벽에 붙은 긴 가구를 돌리면 밖으로 나갈 수 있고 경고만 함.
5. 홀수 치수의 0.5 mm 어긋남(알려진 한계).
6. `item-row`에 계약 밖 `data-warning`과 "경고" 표시.

실기기에서만: iOS Safari에서 추가 탭 시 `blur()`가 값을 확정하고 키보드를 닫는지, 터치 끌기 감각, iOS의 `input type="color"`.
