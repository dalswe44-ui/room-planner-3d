# T-035 보고 (scene-engine): 칸막이 벽, 문·창문, 구역 이름표, 구조 편집 모드 포인터

(scene-engine 에이전트의 최종 보고를 헤드가 이 경로에 옮겨 적었다. 스크린샷 경로 /tmp/t035는 작업 환경의 임시 폴더라 저장소에는 없다.)

## 1. 한 일 (src/scene/만 수정)
새 파일
- `structureGeometry.ts`(+`.test.ts`): 개구부로 자른 벽 조각 `cutWallPieces`, `drawnWall`, `openingsOnWall`, `openingBox`, `doorPlan`(문짝 선·열림 호), `windowPlanLines`, `straightenPreview`, `wallRectCorners`. 위치·열림은 contracts/structure.ts의 `wallSegment`, `openingSpan`, `doorHinge`로 계산.
- `Openings.tsx`: 평면은 문짝 선·열림 호·창문 이중선, 3D는 90도 열린 문짝과 반투명 유리. 구간 전체를 덮는 보이지 않는 눌림 상자.
- `Outlines.tsx`: 선택 테두리, 그리는 중인 벽 점선.
- `structurePointer.test.ts`: 레이캐스트 우선순위, `pickStructure`, `StructureRouter` 라우팅, 경고 규칙.

수정 파일
- `Room.tsx`: 바깥 벽·칸막이를 개구부로 자른 조각으로 그림. 평면은 개구부 구간을 비우고, 3D는 인방·창 아래·창 위를 남김. 칸막이마다 보이지 않는 전체 자리 메시(probe용).
- `SceneView.tsx`: `structureHandlers` prop, `StructureRouter`, 구조 모드 분기, "벽·문 편집 중" 표시(`structure-mode-badge`), wallPreview 점선.
- `gestures.ts`, `pointer.ts`(`chooseStructureHit`, `pickStructure`; `pickFurniture`는 칸막이도 가림막), `camera.ts`(카메라 쪽 바깥 벽의 개구부도 숨김), `geometry.ts`(`isWarningStatus` = overlap‖outside‖wall‖door), `overlayMath.ts`(`wallDimLine`), `SceneOverlays.tsx`(이름표 DOM `area-label`, `wall-dim`, `wall-preview-dim`), `scene.css`, `sceneProbe.ts`(walls, openings, labels, editMode).

동작
- 구조 모드 레이캐스트: 문·창문 > 칸막이 > 바깥 벽(문·창문은 0.15 m 여유 안에서 우선). 가장 가까운 것이 가구면 빈 곳.
- 평면 빈 바닥: 누름 → onBackgroundPointerDown, 이동 → onPointerMove, 뗌 → onPointerUp, 6 px 이내면 onBackgroundTap. 카메라 팬 없음. 3D 빈 곳은 카메라 회전, 짧은 탭만 onBackgroundTap.

## 2. 실행한 명령과 결과 (에이전트 보고)
- `npm run typecheck` 통과, `npm run lint` 통과

- 임시 진입점에서 Playwright(Chrome)로 평면·3D·선택·미리보기 스크린샷과 모의 핸들러 호출 확인. 문 호 방향 4개 모두 `doorHinge`와 일치.
- 헤드 재확인: 인계 직후 `npm run typecheck` 통과.
