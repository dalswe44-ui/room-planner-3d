# T-002c 작업 보고 (room-input)

길이 입력 칸의 오류 문구가 나타나거나 사라질 때 아래 버튼이 밀리는 문제를 고쳤습니다. 방법 A(오류 줄 높이 고정)를 적용했고, 다만 높이를 1줄에서 2줄로 늘렸습니다. 1줄로는 320px 폭에서 문구가 두 줄이 될 때 막을 수 없었습니다.

## 변경 파일

| 파일 | 내용 |
|---|---|
| `src/ui/LengthInput.tsx` | 오류 줄 래퍼 `.length-input__error-line`을 항상 렌더링. 오류 `<p>`(id, role, `<testId>-error`)는 오류가 있을 때만 그 안에 넣음 |
| `src/ui/ui.css` | 둘째 줄을 `auto`에서 고정 `calc(18px * 2)`(36px)로 변경. 래퍼에 `grid-column: 1 / -1; align-self: start`를 주고, `.length-input__error`의 `grid-column` 제거 |
| `src/ui/LengthInput.test.tsx` | `describe('LengthInput 오류 줄 자리')` 추가(테스트 3개) |
| `src/ui/__tmp_preview/` | 삭제. T-002b가 만든 미리보기(`index.html`, `main.tsx`)였고 저장소 안에서 참조하는 곳이 없었음 |

## 방법과 근거

- 수정 전에는 줄 높이가 `minmax(18px, auto)`였습니다. 오류 문구가 두 줄이 되면 줄이 36px로 늘어나 버튼이 움직였습니다.
- 줄 높이를 고정하고 높이를 가진 요소를 항상 DOM에 두면, 문구의 유무와 줄 수에 관계없이 칸의 높이가 같습니다.
- `<testId>-error`는 오류가 있을 때만 존재하므로 기존 테스트의 `toBeNull` 검사를 그대로 통과합니다. 새 `data-testid`는 추가하지 않았습니다(CONTRACT 8절 변경 없음).

## 실제 브라우저 측정

Chrome(`/usr/bin/google-chrome`)과 Playwright로 임시 미리보기 페이지를 띄워 측정했습니다. 측정 스크립트는 `/tmp/t002c/`에 있고 저장소에는 넣지 않았습니다. 측정값은 "칸 위쪽 기준 버튼 위치의 차이"와 "칸 컨테이너 높이"입니다. `.app-panel`이 스크롤 컨테이너라 문서 좌표는 포커스 이동에 흔들리므로 쓰지 않았습니다.

| 조건 | 수정 전 (예약 줄 1줄, 구조 재현) | 수정 후 |
|---|---|---|
| 1280px, 360px | 오류 전후 변화 없음 | 오류 전후 변화 없음 |
| 320px, 280px | 오류가 나타나면 버튼이 18px 내려가고, 사라지면 올라감 | 변화 없음 (차이 270px, 컨테이너 86px 고정) |
| 320px, 버튼 아래쪽 가장자리를 누름 (오류 상태에서 올바른 값 입력 후) | 클릭 0건 | 클릭 1건 |
| 320px, 버튼 중앙을 누름 | 클릭 1건 | 클릭 1건 |
| 360px, 버튼 아래쪽 가장자리를 누름 | 클릭 1건 | 클릭 1건 |
| 280px 메시지 줄 수 | 2줄 | 2줄 (36px 안에 들어감) |

수정 전 값은 실제 구버전 파일을 되돌린 것이 아니라, 브라우저에 CSS를 주입해 이전 구조를 흉내 낸 측정입니다.

## 테스트로 확인한 것과 못 한 것

- jsdom으로 확인한 것: 오류 줄 요소가 칸마다 하나 있고 오류가 없을 때도 비어 있으며, 문구가 나타나거나 사라져도 같은 노드로 남는 것.
- jsdom은 CSS 높이를 계산하지 않으므로 높이 자체는 테스트하지 않았습니다. 높이는 브라우저 측정으로 확인했습니다.

## 남은 문제

1. 실기기(iOS Safari, Android)에서는 확인하지 못했습니다. T-002b의 미해결 3번(입력 칸 포커스가 버튼 탭에서 사라지는지)도 그대로 남아 있습니다.
2. 280px보다 좁은 폭은 측정하지 않았습니다. 문구가 3줄 이상이 되면 다시 밀릴 수 있습니다.
3. 2줄을 예약하므로 모든 길이 칸 아래에 18px 빈 공간이 항상 있습니다. 의도한 비용입니다.
4. T-002b 미해결 2번(거부 상태인 칸이 사라질 때 `true`를 부를지)과 4번(가구 추가 폼의 Enter 제출)은 이번 작업의 범위 밖이라 그대로입니다.
