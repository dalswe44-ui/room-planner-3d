# T-002 작업 보고 (room-input)

> room-input이 최종 응답으로 돌려준 보고 내용을 헤드가 옮겨 저장한 것이다.

T-002는 완료 기준 7개를 모두 충족했고 typecheck, lint, test가 통과했다. 헤드가 정해야 할 것은 4절의 `LengthInput` 계약 문제 하나다.

## 1. 한 일 (변경 파일 목록)
전부 새 파일이고, `src/ui/`와 `src/room/` 밖은 고치지 않았다.

| 파일 | 내용 |
|---|---|
| `src/ui/LengthInput.tsx` | 공용 길이 입력 칸 (props는 CONTRACT 5절 그대로) |
| `src/ui/UnitToggle.tsx` | `unit-mm`·`unit-cm`·`unit-m` 버튼 3개 |
| `src/ui/ui.css` | 위 두 부품의 CSS |
| `src/room/RoomPanel.tsx` | 폭·깊이·천장 높이 칸과 단위 확인 경고 |
| `src/room/room.css` | RoomPanel의 CSS |
| `src/ui/LengthInput.test.tsx` | 테스트 29개 |
| `src/ui/UnitToggle.test.tsx` | 테스트 4개 |
| `src/room/RoomPanel.test.tsx` | 테스트 16개 |

위임 메시지에 없어서 직접 정한 동작:
- 같은 값 확정: 확정한 값이 현재 `valueMm`과 같으면 `onCommit`을 부르지 않고 칸의 글자만 정리한다.
- 거부된 글자: 칸에 그대로 남고, 오류는 다음 확정 때까지 유지된다.
- 밖에서 값이 바뀔 때: `valueMm`이나 `unit`이 바뀌면 입력 중이던 글자와 오류를 버리고 새 값으로 맞춘다.
- 오류 문구: "읽을 수 없는 값입니다. 허용 범위: 500 ~ 20000 mm" 또는 "범위를 벗어났습니다. 허용 범위: …". `max`가 없으면 "1 mm 이상".
- 경고 문구: "단위를 확인하세요. 폭이나 깊이가 1000 mm보다 작거나 15000 mm보다 큽니다. 맞는 값이면 그대로 두어도 됩니다." 숫자는 현재 표시 단위로 나온다.
- RoomPanel에 `UnitToggle`을 넣지 않았다.
- RoomPanel에 안내 문장 한 줄: "벽 안쪽에서 잰 길이입니다. 360cm, 3.6m처럼 단위를 붙여 넣어도 됩니다."
- 입력 칸 테두리는 `--ink-soft`, 오류 문구는 글자를 `--ink`로 두고 왼쪽 막대만 `--warn`.

## 2. 실행한 명령과 결과
| 명령 | 결과 |
|---|---|
| `npm run typecheck` | 통과 |
| `npm run lint` | 통과, 경고 없음 |
| `npm run test` | 5개 파일, 72개 통과, 실패 0 (기존 23개 + 새 49개) |

추가 확인:
- 변형 확인: 구현을 일부러 네 가지로 망가뜨려 테스트가 잡는지 봤고 원본으로 되돌렸다. 밖에서 바뀐 값 동기화 제거(5개 실패), 경계값 제외(5개 실패), 렌더마다 글자 덮어쓰기(8개 이상 실패), 경고 경계에 1000·15000 포함(2개 실패).
- 실제 Chrome 측정: 임시 미리보기 페이지를 Vite 개발 서버와 Playwright(시스템 Chrome)로 열어 1280×800과 360×740에서 쟀다. 단위 버튼 3개는 56×44px, 입력 칸 3개는 높이 44px. "3.5" 거부 문구, 999 경고, 입력 중 "1." 유지, m 전환 뒤 표기가 기대대로 나왔다. 콘솔 오류는 404 한 건(어떤 요청인지 확인하지 않음, favicon으로 추정). 임시 파일은 삭제했다.

## 4. 계약·공유 파일 변경 요청
1. (T-004 전에 결정 필요) `LengthInput`은 칸이 지금 잘못된 상태인지 부모에게 알릴 방법이 없다. 가구 추가 폼에서 폭을 비우고 `furniture-add`를 누르면 오류는 뜨지만 폼은 예전 폭으로 가구를 추가하게 되어 SPEC F-2·F-3과 어긋난다. 방법: 선택 prop(`onValidityChange?(valid: boolean)`) 추가, 또는 추가 폼이 `parseLength`로 직접 검증.
2. CONTRACT 5절 설명 보완: "값이 그대로이면 `onCommit`을 부르지 않는다", "`RoomPanel`은 `UnitToggle`을 포함하지 않는다".
3. 조립 시 참고: CSS는 컴포넌트가 import한다. `UnitToggle`과 `RoomPanel` 사이 간격은 `src/app/`에서 정한다.

## 5. 미해결 질문
1. 실기기 확인 필요: `inputMode="decimal"` 키패드에는 iOS에서 글자 키가 없을 것으로 본다. 그러면 휴대폰에서는 "120cm"처럼 단위를 붙여 넣을 수 없고 단위 버튼으로 바꾼 뒤 숫자만 넣어야 한다.
2. 실기기 확인 필요: 소수점을 쉼표로 쓰는 지역 설정의 키패드에서는 "3,5"가 입력될 수 있고 `parseLength`는 이를 거부한다.
3. 오류가 떠 있는 칸을 원래 값으로 되돌리는 방법(예: Esc)은 넣지 않았다.
4. 다른 칸에 입력하던 중 단위 버튼을 누르면 그 칸의 글자는 확정을 시도한 뒤 저장된 값의 새 표기로 바뀐다. 잘못된 글자였다면 오류 없이 버려진다.
5. "3.5" 거부 문구에 단위 확인 문장은 넣지 않았다.
6. 실행 모델 ID는 `claude-fable-5-2`다(`model: sonnet`은 적용되지 않음).
