# T-002b 작업 보고 (room-input)

> room-input이 최종 응답으로 돌려준 보고 내용을 헤드가 옮겨 저장한 것이다.

T-002b는 완료 기준 4개를 모두 충족했고 typecheck, lint, test가 통과했다. 다만 실제 Chrome에서 확인하다가 오류 문구가 나타나거나 사라질 때 칸 아래의 버튼이 밀려 클릭이 사라지는 문제를 발견했다(4절 1번).

## 1. 한 일 (변경 파일 목록)

| 파일 | 내용 |
|---|---|
| `src/ui/LengthInput.tsx` | 선택 prop `onValidityChange?(valid: boolean): void` 추가 |
| `src/ui/LengthInput.test.tsx` | `describe('LengthInput onValidityChange')` 추가(테스트 19개). 기존 테스트 29개는 건드리지 않았다 |

직접 정한 동작:
- 확정(Enter, 포커스 이탈)으로 상태가 바뀌면 그 이벤트 핸들러 안에서 바로 부른다. `valueMm`·`unit`이 밖에서 바뀌어 오류가 사라진 경우만 렌더 뒤(effect)에 부른다. 포커스 이탈 직후의 click이나 Enter 직후의 폼 제출 핸들러가 실행될 때 부모가 이미 값을 받은 상태가 되게 하기 위해서다.
- 처음 그릴 때는 부르지 않는다. 부모는 처음 상태를 "올바름"으로 두어야 한다.
- 거부 상태에서 다시 거부될 때는 다시 부르지 않는다.
- 올바른 값 확정 때 `onValidityChange(true)`를 먼저, `onCommit`을 나중에 부른다.

## 4. 계약·공유 파일 변경 요청

1. (T-004 전에 결정 필요) 오류 문구 때문에 버튼이 밀려 클릭이 사라진다.
   - 원인: 오류 문구는 포커스 이탈(mousedown) 때 나타나거나 사라지므로, 그 순간 칸 아래 요소들이 문구 높이만큼 움직인다. 누른 곳과 뗀 곳의 요소가 달라져 브라우저가 click을 만들지 않는다.
   - 측정: 미리보기에서 문구 높이는 18px, 버튼은 22px 움직였다. mouseup 때 포인터 아래 요소는 오류 문구였다.
   - 오류가 떠 있는 칸을 올바른 값으로 고치고 추가 버튼을 누르면 값은 확정되는데 클릭이 사라져 가구가 추가되지 않는다. 한 번 더 눌러야 한다.
   - e2e F-2에도 영향이 있을 수 있다.
   - 방법 A: `src/ui/ui.css`에서 오류 문구 자리를 항상 비워 둔다. 방법 B: `furniture-add`를 밀리지 않는 자리에 둔다. 권장은 A.
2. CONTRACT 5절 설명 보완: 처음 그릴 때는 부르지 않는다, 확정으로 바뀐 상태는 그 이벤트 안에서 알린다, `onValidityChange(true)`가 `onCommit`보다 먼저다.
3. furniture-placement에 전할 것: 거부 상태인 `LengthInput`이 화면에서 사라져도(unmount) `true`를 부르지 않는다. 선택이 풀리면 사라지는 수정 칸에 이 prop을 쓰면 부모 상태가 `false`로 남는다.

## 5. 미해결 질문

1. 4절 1번을 A와 B 중 어느 쪽으로 할지.
2. 사라지는 칸에서 unmount 때 `true`를 불러야 하는지.
3. 실기기 확인 필요: iOS Safari에서 입력 칸에 포커스가 있는 채로 버튼을 탭하면 칸이 포커스를 잃는지 확인하지 못했다. 잃지 않으면 확정 시도가 없어 예전 값으로 추가될 수 있다.
4. 가구 추가 폼을 `<form>`으로 만들고 Enter로 제출하게 할지는 furniture-placement가 정할 일이다.
5. 실행 모델 ID는 `claude-fable-5-2`다.
