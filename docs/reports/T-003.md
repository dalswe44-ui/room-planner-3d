## 2. 구현한 계약 항목

- 5절: `SceneView(props: { handlers, statuses })`, `ViewToggle()`. store의 `project`, `viewMode`, `selectedItemId`, `dragPreview`를 읽는다.
- 6절: `onItemPointerDown(id, floor)`, `onBackgroundTap()`, `onFloorPointerMove(floor)`, `onPointerUp()` 연결. 끌기 로직과 겹침 판정은 구현하지 않음.
- 7절: `snapshot()`은 메시 위치, 회전, `BoxGeometry.parameters`, 바닥 메시 범위에서 읽는다. `floorToClient(x, z)`는 실제 카메라와 캔버스 rect로 투영한다. 색, 경고, 선택 상태는 메시 userData 표식에서 읽는다.
- 8절: `view-2d`, `view-3d`(aria-pressed), `scene-canvas`.
- three 0.187.0, fiber 9.8.2, drei 10.7.9. 외부 에셋, 그림자, 후처리 없음. `dpr` 최대 2, `frameloop="demand"`.
- 카메라 쪽 벽은 3D 뷰에서 숨기고, 평면 뷰에서는 모두 보인다.
- 가구를 누르면 `OrbitControls`를 끄고, 뗄 때 켠다.

## 3. 검증 결과

| 명령 | 결과 |
|---|---|
| `npm run typecheck` | 통과 |
| `npm run lint` | 통과, 경고 없음 |
| `npm run test` | 11개 파일, 135개 통과(scene 6개 파일 41개). 실패 0 |
| `npm run build` | 통과 |

Chrome 확인(dev 서버 + 임시 진입점, Playwright + `/usr/bin/google-chrome`, swiftshader):
- 프로브가 방 3600 × 3000 × 2400과 가구 2개(중심 1800, 360, 1500 / 크기 1200×720×600)를 읽었다.
- 평면 뷰에서 방 네 모서리가 `scene-canvas` 안에 있고 위아래 여백이 대칭이다.
- 가구를 (1800, 1500)에서 (1000, 800)으로 끌었을 때 중심이 정확히 옮겨졌고 카메라는 움직이지 않았다.
- 빈 곳을 끌면 카메라가 (-80, -40) px 팬했다. 짧은 탭은 `onBackgroundTap` 한 번으로 연결됐다.
- `view-3d`를 누르면 프로브 `view`가 `3d`가 되고 `aria-pressed`가 옮겨 갔다. 3D 스크린샷에서 카메라 쪽 벽이 가려지고 방과 가구가 보였다.
- 확인 중 발견해 고친 버그: 평면 뷰가 약 5도 기울어 옆면이 보였다(OrbitControls의 `maxPolarAngle` 클램프). 평면 뷰에서 각도를 90도로 고정해 해결.

확인하지 못한 것: WebGL 컨텍스트 손실·복구(리스너만 등록), 터치 감각과 iOS Safari(실기기 필요), 경고 색과 선택 테두리의 화면 모습, 회전 방향의 화면 확인(식으로만 검토), `vite preview`로 실제 앱 확인(앱에 장면이 없었음). jsdom에는 WebGL이 없어 R3F 컴포넌트를 직접 렌더링하는 테스트는 쓰지 못했다.

## 4. 남은 문제와 T-004가 알아야 할 점

헤드가 할 일:
- `main.app-scene` 안에 `<ViewToggle />`와 `<SceneView handlers statuses />` 조립. `usePlacement`, `useItemStatuses` 전까지 임시 핸들러.
- `coords.ts`의 `worldToMm`, `worldToRoom`이 작은 음수에서 `-0`을 만들 수 있다. 장면 쪽은 `pointer.ts`에서 `|| 0`으로 정규화했다.

T-004가 알아야 할 것:
- `onItemPointerDown`의 `floor`는 누른 지점의 바닥 좌표이지 가구 중심이 아니다. 누른 지점과 중심의 차이(grab offset)를 저장해 두고 끌어야 가구가 점프하지 않는다.
- `onPointerUp`은 `pointercancel`에서도 불린다. `onBackgroundTap`은 빈 곳을 6 px 이내로 움직이고 떼었을 때만, 두 손가락 제스처 뒤에는 불리지 않는다.
- 누르는 동안 카메라 조작은 꺼진다. 끌기 중 임시 위치는 `dragPreview`로 넘기면 장면이 그 위치와 현재 회전으로 그린다.
- 겹침·이탈 경고는 `statuses`의 `overlap || outside`로 빨간색(`#e5484d`)으로 그린다. 끄는 중에도 `useItemStatuses`가 `dragPreview`를 반영해야 한다.

열린 질문:
- 3D 뷰에서도 가구 누름이 `onItemPointerDown`을 부른다. SPEC은 끌기를 평면 뷰로 정했으므로 3D에서 끌기를 막을지.
- 벽 두께 100 mm, 벽·바닥 색, 선택 테두리 색은 SPEC에 없는 제안 값.

계약·공유 파일 변경 요청: `App.tsx` 조립, `coords.ts`의 `-0` 정규화.
