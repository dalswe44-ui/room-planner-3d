# T-018 보고 (scene-engine): 새로 고침으로 불러온 가구의 이름표가 보이지 않던 결함

발견: 헤드가 배포 페이지(1cacaf4)에서 새로 고침 뒤 이름표가 없는 것을 보고 로컬 preview로 재현(reload 전 1개, 후 0개).

## 1. 원인과 수정
- 변경: `src/scene/Furniture.tsx`의 FurnitureLabel만(+9줄). 저장 쪽은 원인 아님.
- 원인: drei Html은 붙일 요소를 렌더마다 `portal ?? events.connected ?? gl.domElement.parentNode`로 고르고(drei/web/Html.js:123), 이 값이 effect 의존성이다(159행). R3F는 events.connected를 첫 그림 뒤에 채운다. 자동 저장 불러오기(T-015)가 첫 그림 전에 가구를 넣으면, Html이 connected가 null일 때(대상 = 캔버스 부모) 마운트되고 곧 대상이 바뀐다. 그때 앞 루트의 unmount가 "렌더 중"이라 미뤄지고(dev 콘솔 "synchronously unmount a root while React was already rendering"), 미뤄진 해제가 새 루트가 그린 이름표를 지운다. 결과: `.furniture-label-wrap`은 있는데 안이 빔. 사용 중 추가한 가구는 connected가 이미 있어 정상.
- 수정: `events.connected`가 채워지고 한 틱(setTimeout 0) 지난 뒤에만 Html을 만든다. 숨긴 오류·재시도 없음(붙일 곳이 정해지기 전에는 만들지 않음).

## 2. 증거
- 수정 전 prod: reload 후 items 1, labels 0, wraps 1(빈 div). dev: labels 0 + 위 콘솔 오류.
- 임시 계측: reload 뒤 connected null(2회) → 요소(2회)로 바뀐 직후 오류.
- 실험 1(connected 게이트만): prod는 해결, dev(StrictMode)는 여전히 실패. 실험 2(게이트 + 한 틱): dev·prod 모두 labels 1, 오류 없음.
- typecheck·lint 통과, test 332, e2e 97 passed + 12 skipped.
